## 环境与执行范围

管控台 `http://127.0.0.1:18104/`、Server `18084`、Remote Gateway `18094`，连接独立 profile 的真实 npm Harness `0.2.1-rc.5` Host。浏览器为 Codex IAB。Server 使用真实 PostgreSQL 和 Redis。本轮没有更新 NAS，也没有提交或推送代码。

请求经过浏览器 Cookie ticket、Noise 加密连接、Relay、目标 Host 和企业模型网关，最终访问用户指定的 `https://discovery-api.intern-ai.org.cn/v1`。Java 继续协调链路并转发密文，会话、文件、终端仍由目标 Host 执行。模型协议使用官方 `dsh-llm-pi-ai`，没有新增供应商适配器。

管理端通过正常模型接入和成员授权 API 登记 `Atria-Dawn · 真实模型验收`，`GET /models` 返回 200 并包含 `Atria-Dawn`。随后调用既有 Host 显式刷新 API，使模型进入目录；当前设计没有闲置模型目录轮询。测试配置为 `openai-completions`、32768 上下文和 4096 最大输出，这两个数值是测试参数，不代表供应商能力上限。

测试只操作隔离工作区的 `atria-remote-20261112/`。API Key 只用于指定模型接入，临时来源文件权限为 0600；受版本管理的源码和证据不包含密钥。原有本机固定回复模型夹具保持独立，本轮真实模型结果没有使用该夹具。

## 用量与中断边界

服务端按此真实模型过滤得到 18 条请求记录，其中 17 条为 `SETTLED`，包含上游 request ID；另 1 条是手动停止的流式请求，终态为 `CHARGED_MAX`。

17 条已知用量合计 308594 Token，包含缓存 Token。停止请求没有最终 usage，既有策略按预留上限扣额 29670 Token，没有把未知用量当成实测 0。平台扣额合计为 338264 Token。这是平台配额账，不代表供应商的实际账单或价格。

原生界面的约 309K 用量只反映收到的已知 usage。不能将“停止生成成功”解释为供应商未消耗 Token，或解释为立即退还该次全部配额。此规则沿用现有网关计量设计，本次没有修改计费逻辑。
