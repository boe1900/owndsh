一个控制面，两个工作面。

管理员在一处治理团队资源；成员在熟悉的官方界面里工作。一个标准插件，连接两端。

产品控制台

企业管理员 · 模型管理员 · 插件管理员 · 审计员

配置身份源与成员、接入供应商与模型、设定授权与配额、发布插件 / 技能 / MCP，查询用量与审计。

  • LOCAL / LDAP / OIDC，接着用团队已有的账号体系

  • 每一次调用与操作，都有用量与审计可查

员工 · 一个插件 / 一个桌面应用

从一条命令，到你的团队控制面。

● Docker Compose · 服务端amd64 / arm64
git clone https://github.com/boe1900/owndsh.git
cd owndsh
docker compose up -d --wait
● 生产部署 · .env 必改项cp .env.example .env
# 对外访问地址：跨设备 / 公网必改（管理回调自动派生）
ENT_PUBLIC_BASE_URL=https://owndsh.example.com

# 四个开箱测试密钥，公网部署必须全部替换
ENT_POSTGRES_PASSWORD=<强密码>
ENT_REDIS_PASSWORD=<强密码>
SA_TOKEN_JWT_SECRET_KEY=<随机长串>
ENT_MASTER_KEY=<32 位随机十六进制>

# 初始管理员密码（首次登录后仍会强制设置正式密码）
ENT_BOOTSTRAP_ADMIN_PASSWORD=<强密码>

部署完成后访问 ENT_PUBLIC_BASE_URL 配置的地址，账号 admin，密码为你在 ENT_BOOTSTRAP_ADMIN_PASSWORD 设置的值——未设置时为 owndsh；首次登录都会强制设置正式密码。

HTTPS 由你现有的网关终止；备份、恢复与离线升级的完整清单见部署文档。

05 /A FEW GOOD QUESTIONS

开始之前。

三个最常被问到的问题。在 GitHub 交流

OwnDsh 和 DeepSeek Harness 是什么关系？+

OwnDsh 是独立的开源项目，不隶属于 DeepSeek AI。它通过官方公开的插件扩展点，为现有 Harness 增加团队治理能力；DeepSeek Harness 与 DSH Desktop 的名称、代码与商标归各自所有。

成员需要自己的模型 API Key 吗？+

不需要。管理员在服务端配置供应商密钥并授权模型；成员用企业账号登录，每次请求由网关重新校验身份、授权和额度。密钥不出服务端。

团队已经在用 LDAP 或 OIDC，能接吗？+

能。LOCAL、LDAP、OIDC 三类身份源按需启用：LDAP 支持目录搜索、单人导入与组映射，OIDC 走标准登录——团队账号体系接着用，不用重建人员。
